# UI/UX

Antes de cambiar una interfaz, inspecciona componentes, tokens, patrones y estados existentes. Conserva la coherencia del sistema antes de introducir variantes.

- Diseña la jerarquía y el flujo antes del pulido visual.
- Considera WCAG 2.2 AA cuando corresponda y remite a `convenciones-frontend` y `accesibilidad` para reglas específicas.
- Define comportamiento por capacidades y tamaños, no solo por dispositivos.
- Haz alcanzables los estados de carga, vacío, error, éxito, deshabilitado y permisos.
- Usa feedback comprensible y microinteracciones que no dependan solo de color o movimiento.

Carga [CRITERIOS-UI-UX.md](references/CRITERIOS-UI-UX.md) bajo demanda. Estructura de codigo: `convenciones-frontend`; accesibilidad: `accesibilidad`; ejecucion de diseno: `impecable`/`impeccable`.
